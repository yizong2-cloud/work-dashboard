> **用途**：帮助 Agent 在分析飞书聊天记录时，正确识别/合并任务，避免把「同一个任务在不同群里的讨论」误判成多个任务；同时记录飞书之外的信息（面聊、口头确认、领导指示）。

> 1. 每次更新看板前先读本文件；分析出新的任务合并依据、口头确认、依赖关系时，**先写入第七节「待确认区」**（含来源与时间），**用户确认后**再移入「已确认事实」——禁止把推测直接固化为永久事实。
> 2. 若用户当面/对话直接确认了某事实，可直接写入「已确认事实」，来源标注**用户口头**。
> 3. 本文件表格改动时保持分隔行（`|---|`）完整，不要用脚本批量去重（会误删同日期多条事实）。

## 四、任务合并 / 拆分判定规则

1. **先查本表**：新聊天里出现的任务描述，先对照「别名映射」找已有任务，命中则不新建。
2. **同一产品 + 同一功能**的讨论（即使在不同群）→ 合并为一个任务，把新信息追加到该任务时间线。
3. **不同产品线**即使名字相似（如 peace sdk vs jigsaw-cy sdk）→ 不合并。
4. **拿不准**：宁可先不动，把疑似合并点记录下来问用户。
5. 分析完成后，把本次发现的新别名、新事实追加到本文件「一、二」节。
